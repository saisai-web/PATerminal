# Security Policy

## Reporting a vulnerability

Do not open a public Issue for a suspected vulnerability or include exploit details in a public discussion.

Email **k-saiki@yotsuba-system.co.jp** with:

- the affected PATerminal version and operating system;
- a concise description of the issue and its impact;
- reproduction steps or a minimal proof of concept;
- any suggested mitigation; and
- a safe way to contact you for follow-up.

Please remove license keys, access tokens, private repository content, terminal history, personal data, and other secrets from reports. If sensitive supporting material is necessary, first ask for a safe transfer method.

You should receive an acknowledgement within seven calendar days. We will investigate, coordinate a fix and disclosure timeline when applicable, and credit reporters who request attribution. We cannot promise a bounty or a particular release date.

## Supported versions

Security fixes are normally made for the latest official release. Self-built and modified copies do not receive a compatibility, signing, update, or security-maintenance guarantee under the EULA.
